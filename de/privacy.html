Kein Nutzer-Tracking, keine Cookies, Profile oder gespeicherten Besucher-/Analytics-Kennungen. Nur grobe tägliche Ereigniszähler.

Was diese Site macht

cruxcoach.org liefert statische HTML-, CSS-, SVG- und PNG-Dateien aus. Die Seiten setzen keine Cookies, binden kein Drittanbieter-Analytics ein und laden keine Drittanbieter-Skripte oder -Schriften. Das gesamte JavaScript, CSS und Bibliotheks-Material wird von cruxcoach.org selbst ausgeliefert — keinerlei CDN-Abhängigkeiten. Die First-Party-Komponenten senden ausschließlich die unten beschriebenen anonymen Aggregat-Ereignisse.

Jeder Direkt-APK-Button trägt einen einfachen versionierten Codeberg-Link. Ein Klick lädt das Release deshalb auch dann herunter, wenn JavaScript aus ist, ein Privacy-Signal gesetzt ist oder unser eigener Server nicht erreichbar ist. Sobald der Seitenaufruf-Zählrequest bestätigt hat, dass stats.cruxcoach.org antwortet, richtet dasselbe Skript den Button stattdessen auf unseren First-Party-Selector dort. Diese Antwort liegt ohnehin schon vor, es entsteht also keine zusätzliche Anfrage und kein Dritter wird kontaktiert. Auf diesem Weg liefert der Selector das Release aus einer Kopie auf genau diesem Server aus — der Download berührt damit keinen Dritten: keine deiner Anfragen erreicht Codeberg oder Zapstore, und keiner von beiden erfährt, dass du etwas geladen hast. Ein Hintergrundprozess liest laufend das unter /apk-target.json veröffentlichte Release-Manifest und prüft unsere Kopie gegen dessen SHA-256; ausgeliefert wird nur eine byte-genaue Kopie. Fehlt sie oder passt sie nicht, weicht der Selector auf Codeberg aus (eine Weiterleitung) und danach auf Zapstore (über diesen Server durchgereicht, weil Zapstore inhaltsadressiert ist und eine Weiterleitung dorthin deinem Browser eine namenlose 64-Zeichen-Datei übergeben würde). Dein Browser sendet in keinem Fall eine Verfügbarkeitsanfrage.

Dass wir die Datei selbst ausliefern, heißt: dieser Server sieht die Übertragung — Dauer, Menge und ob du abgebrochen hast — für ihre Laufzeit, statt nur deinen Klick. Gespeichert wird davon nichts: der aggregierte Zähler erhält denselben einzelnen Install-Klick, ohne Adresse, ohne User-Agent, ohne Log. Der Tausch ist beabsichtigt und fällt zu deinen Gunsten aus: zuvor wurde jeder Download von einem Dritten beobachtet, für den wir nichts zusagen können.

Einige Seiten enthalten JavaScript, jeweils nur für das, was die Seite konkret braucht:

  • /boards/ rendert eine interaktive Karte von Climbing-Board-Standorten. Genutzt wird eine lokal gehostete Kopie der Open-Source-Bibliothek Leaflet; der Datensatz (/boards/data/boards.geojson) liegt ebenfalls auf dieser Site. Sie speichert außerdem deine letzte Kartenposition und Filterauswahl im localStorage deines Browsers, damit ein Neuladen der Seite deine Ansicht wiederherstellt — diese Daten bleiben auf deinem Gerät und werden nicht übertragen. Die Karten-Kacheln (Tiles) kommen jedoch von einem Drittanbieter — siehe nächster Abschnitt.
  • Die Ortssuche auf /boards/ kontaktiert keinen Geocoder. Beim ersten Tippen im Suchfeld lädt die Seite eine weitere statische Datei von dieser Site (/boards/data/cities.json, erzeugt aus GeoNames-Daten unter CC BY 4.0) und gleicht deine Eingabe lokal dagegen ab. Was du tippst, verlässt deinen Browser nicht.
  • Der Standort-Button auf /boards/ ist die einzige Funktion, die eine Browser-Berechtigung anfragt. Wenn du ihn aktivierst und die Anfrage erlaubst, ermittelt dein Browser deine Position, die Karte zentriert darauf und zeichnet einen Punkt samt Genauigkeitskreis. Die Koordinaten dienen ausschließlich dazu, die Karte innerhalb der geöffneten Seite zu bewegen: Sie werden weder an diese Site noch an den Tile-Server noch an sonst jemanden übertragen und nirgends gespeichert. Lehnst du die Abfrage ab oder drückst den Button nie, bleibt die Karte unverändert.
  • /404.html öffnet bei Aufruf einer /c/<naddr>-URL WebSocket-Verbindungen zu öffentlichen Nostr-Relays (relay.damus.io, nos.lol, relay.primal.net), um Metadaten zu einem geteilten Climb abzurufen. Es werden keine Daten gesendet außer der Standard-Nostr-Query.

Anonyme Aggregat-Zähler

Beim Laden einer Seite sendet das lokale Skript /assets/anonymous-analytics.js einen First-Party-Zählrequest an stats.cruxcoach.org; einen weiteren sendet es beim Aktivieren der Zapstore-Installationsoption. Eine Direkt-APK-Aktivierung wird durch denselben First-Party-Request gezählt, der eine verfügbare APK-Quelle auswählt und ausliefert; JavaScript sendet sie deshalb nicht ein zweites Mal. Wurde der Button nie auf diesen Selector gerichtet, weil unser Server nicht geantwortet hat, zählt das Skript die Aktivierung selbst — sonst sähe eine Störung wie fehlendes Interesse aus. Das Skript kann zusätzlich einen Zapstore→Direkt-APK-Fallback im selben Tab wie unten beschrieben zählen. Ist Do Not Track oder Global Privacy Control im Browser aktiviert, sendet das Skript nichts, legt keinen Fallback-Marker an und der Selector überspringt seinen Zähler, führt die Download-Weiterleitung aber weiterhin aus.

  • Ein Seitenaufruf enthält nur einen kanonischen Seitennamen wie /, /boards/ oder /privacy.html. Karten- und Listenansicht der Board Map verwenden dasselbe Label /boards/; Deutsch und Englisch bleiben getrennt. Query-Strings, Fragmente, Referrer und vollständige URLs werden nicht gesendet. Jeder /c/<naddr>-Share wird auf dasselbe Label /c/:share reduziert; die Share-Kennung erreicht den Zähler nie.
  • Ein Installationsklick enthält nur das Ziel (direct_apk oder zapstore), die Platzierung (hero, install oder shared_climb) und denselben kanonischen Seitennamen. So lassen sich öffentliche Unterseiten unterscheiden, ohne vollständige URL, Query oder Share-Kennung zu übertragen.
  • Nach einer Zapstore-Aktivierung speichert das Skript ausschließlich deren Zeitpunkt im sessionStorage des aktuellen Tabs. Der Wert enthält keine zufällige oder beständige Kennung, wird nie übertragen, verfällt nach 30 Minuten, wird beim ersten nachfolgenden Direkt-APK-Klick gelöscht und verschwindet mit dem Ende der Tab-Sitzung. Erfolgt dieser Direkt-Klick innerhalb von 30 Minuten, erhält der Server ein einziges, bereits kombiniertes Fallback-Ereignis nur mit der kanonischen Seite. Er erhält weder zwei verknüpfbare Ereignisse noch die Zeitdifferenz. Der Zähler ist ein Interaktionshinweis, kein Beweis dafür, dass Zapstore fehlgeschlagen ist oder jemanden abgeschreckt hat.
  • Die Skript-Requests lassen Credentials und Referrer ausdrücklich weg; Direkt-APK-Links und Redirect-Antworten setzen ebenfalls eine No-Referrer-Policy. Es werden keine Cookies, Local-Storage-Analytics-ID, Account-/Nostr-Schlüssel, Geräte-ID, Fingerprints, Bildschirmdaten, IP-Hashes oder Session-/Besucherkennungen erzeugt oder übermittelt. Der Selector liest einen DNT-/GPC-Header nur, um die Zählung zu unterdrücken, und bewahrt ihn nicht auf.

Der Collector erhöht sofort ein freigegebenes UTC-Tagesaggregat und behält weder Rohereignis noch exakten Zeitstempel, Request-Header, IP-Adresse, User-Agent oder Referrer. Sein eigenes Request-Logging und das Access-Logging des dedizierten Reverse-Proxys sind deaktiviert. Eine IP-Adresse wird von der Netzwerkinfrastruktur für die Zustellung des Requests zwangsläufig kurzzeitig verarbeitet; sie wird von unserem Analytics-Stack jedoch weder in den Ereignis-Payload oder Aggregatdatensatz übernommen noch protokolliert, gehasht oder aufbewahrt. Die Zahlen sind Seitenaufrufe, Klicks und eine ausdrücklich definierte Fallback-Folge — niemals Zählungen von Personen, serverseitigen Sessions oder eindeutigen Besuchern. Sie sind Näherungswerte: Privacy-Signale, Blocker, Ausfälle, Neuladen, wiederholte Klicks, direkt aufgerufene Selector-Links, Bots und gefälschte Requests können sie beeinflussen. Quellcode von Collector und Dashboard wird in einem privaten Betriebs-Repository gepflegt und ist nicht öffentlich zugänglich. Das betrifft nicht die CruxCoach-Android-App: Ihr Quellcode bleibt unter codeberg.org/CruxCoach/CruxCoach als Open Source öffentlich verfügbar.

Verantwortlicher, Zweck und Rechtsgrundlage

Wir nutzen die Website-Zähler ausschließlich, um zu verstehen, welche öffentlichen Seiten geladen werden, Aktivierungen der beiden Installationsoptionen und die grobe Zapstore→Direkt-APK-Fallback-Quote zu zählen und Site sowie Download-Wege zu betreiben und zu verbessern. Ab der geplanten App-Version 0.2.2 zeigt der Zähler für verifizierte Updates zusätzlich die aggregierte Updater-Verteilung nach Zielversion und Quelle, damit wir Nutzung und Zuverlässigkeit dieses Verteilungswegs beurteilen können. Unsere berechtigten Interessen sind der datensparsame Betrieb, die Wartung und Verbesserung dieses nichtkommerziellen Open-Source-Projekts und seiner Download-Verteilung. Wir nutzen die Daten nicht für Werbung, Profiling, das Wiedererkennen von Personen oder das Zählen eindeutiger Besucher.

Analytics-Hosting, Empfänger und Speicherdauer

Der Endpunkt stats.cruxcoach.org läuft auf Infrastruktur der Hetzner Online GmbH am gewählten Standort Helsinki, Finnland. Hetzner stellt die Hosting-Infrastruktur bereit und verarbeitet bei der Zustellung des Netzwerkverkehrs zwangsläufig Verbindungsdaten. Der Collector liegt nicht hinter einem Analytics-CDN oder einer WAF. Das Access-Logging des dedizierten Reverse-Proxys und das Request-Logging des Collectors sind deaktiviert; unser Analytics-Stack bewahrt weder Rohrequest noch IP-Adresse, User-Agent, Referrer oder exakten Zeitstempel auf. Der APK-Selector hält separat nur öffentliche Release-Metadaten und die aktuell ausgewählte Quelle im Cache, niemals Besucherdaten.

Akzeptierte Requests werden sofort in UTC-Tageszähler überführt. Diese Aggregate werden nach metrics_anonymous.csv im privaten Betriebs-Repository exportiert und nicht öffentlich veröffentlicht. Sie werden ohne feste Löschfrist einschließlich der Repository-Historie aufbewahrt. Sie enthalten kein Rohereignis und keine Kennung und können weder eine Person identifizieren noch getrennte Server-Ereignisse verknüpfen; die Fallback-Folge wird bereits lokal vor ihrem einzigen Request kombiniert.

Karten-Kacheln auf /boards/

Der Karten-Hintergrund auf /boards/ wird aus OpenStreetMap-Raster-Tiles gerendert, die von tile.openstreetmap.org ausgeliefert werden. Solange diese Seite geöffnet ist, sendet dein Browser direkt Anfragen an diesen Host für jede benötigte Kachel. Diese Anfragen unterliegen der Tile-Usage-Policy sowie der Datenschutzerklärung der OpenStreetMap Foundation. Wir haben keinen Einblick in diese Anfragen; die einzige Möglichkeit, sie zu vermeiden, ist, die Karte nicht zu laden.

Externe Links

Es gibt keine besucherseitige oder vor dem Klick ausgelöste APK-Verfügbarkeitsprüfung. Der First-Party-Server prüft die Quellen ohne Besucherdaten. War der Button auf unseren Selector gerichtet, fragt dein Browser bei Aktivierung zuerst nach, ob stats.cruxcoach.org überhaupt noch antwortet — der Server kann seit dem Laden der Seite ausgefallen sein — und kontaktiert ihn dann; er liefert die Datei entweder selbst aus oder leitet zur ausgewählten Codeberg- oder Zapstore-Quelle weiter, erst danach verbindet sich dein Browser mit diesem Anbieter. Diese erste Frage geht an unseren eigenen Server über ihn selbst und wird nicht gezählt. War er es nicht — weil unser Server nicht geantwortet hat oder weil du ein Privacy-Signal gesetzt hast — verbindest du dich direkt mit Codeberg. Nur in dieser Lage fragt das Skript zuvor Codebergs Release-Metadaten ab, höchstens 1,5 Sekunden lang, und schickt dich zum Zapstore-Spiegel, falls das Release dort nicht mehr liegt. Diese Frage wird erst nach deinem Klick gestellt, nur wenn unser eigener Server nicht erreichbar ist, und nur an den Anbieter, zu dem dein Klick ohnehin unterwegs war; beim bloßen Lesen der Seite passiert das nie, und die APK-Datei selbst wird dafür nicht angefordert. Andere externe Links verbinden sich beim Anklicken direkt. Diese Dienste haben eigene Datenschutzpraktiken, die ab dem Verbindungsaufbau gelten:

Die CruxCoach-Android-App

Diese Seite beschreibt hauptsächlich die Website cruxcoach.org. Die CruxCoach-Android-App hält persönliche Daten standardmäßig lokal, hat kein Nutzer-Tracking und keine Accounts und bietet ein optionales verschlüsseltes Backup. Die aktuelle Version 0.2.1 sendet kein App-Analytics-Ereignis. Für Version 0.2.2 ist ein Aggregat-Inkrement vorgesehen, nachdem der optionale In-App-Updater ein Update vollständig geladen und dessen SHA-256 sowie Signaturzertifikat geprüft hat. Das Ereignis wird ausschließlich Zielversion und Quelle (codeberg/zapstore) enthalten, nie eine Geräte-, Installations-, Account-, Nostr-, Werbe- oder Nutzerkennung. Ein fehlgeschlagener Zählrequest wird Update-Prüfung und Installation nie beeinflussen. Gezählt werden dann verifizierte Updater-Downloads, nicht Personen oder erfolgreiche Installationen. Das vollständige Netzwerk-Verhalten der App ist auf der Hauptseite sowie im Quellcode-Repository unter codeberg.org/CruxCoach/CruxCoach beschrieben.
