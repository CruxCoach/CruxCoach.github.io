Privacy

No user tracking, cookies, profiles, or stored visitor/analytics identifiers. Only coarse daily event counters.

What this site does

cruxcoach.org serves static HTML, CSS, SVG, and PNG files. The pages set no cookies, load no third-party analytics, and load no third-party scripts or fonts. All JavaScript, CSS, and library code that the site uses is served from cruxcoach.org itself — there are no CDN-hosted dependencies. The first-party components send only the anonymous aggregate events described below.

Every direct-APK button carries a plain versioned Codeberg link, so one click downloads the release even with JavaScript switched off, with a privacy signal set, or while our own server is down. Once the page-view counter request has confirmed that stats.cruxcoach.org is reachable, the same script points the button at our first-party selector there instead. That answer has already arrived on its own, so this costs no additional request and contacts no third party. Over that route the selector serves the release from a copy held on that same server, so the download involves no third party at all: no request of yours reaches Codeberg or Zapstore, and neither of them learns that you downloaded anything. A background process keeps checking the release manifest published at /apk-target.json and verifies our copy against its SHA-256; only a byte-exact copy is served. Should it be missing or not match, the selector falls back to Codeberg (a redirect) and then to Zapstore (relayed through this server, because Zapstore is content-addressed and a redirect there would hand your browser a name-less 64-character file). Your browser makes no availability request in any case.

Serving the file ourselves means this server sees the transfer — its duration, its volume, and whether you cancelled — for as long as it runs, rather than only your click. Nothing about it is stored: the aggregate counter records the same single install-click increment, with no address, no user agent and no log. The trade is deliberate, and it moves in your favour: previously every download was observed by a third party we cannot make promises about.

Some pages contain JavaScript, and only for the feature each one needs:

  • /boards/ renders an interactive map of climbing-board locations. It uses a locally-hosted copy of the open-source Leaflet library, and loads its dataset (/boards/data/boards.geojson) from this site. It also saves your last map position and filter selections in your browser's localStorage so a page reload restores your view — that data stays on your device and is never transmitted. The map tiles, however, are fetched from a third-party tile server — see the next section.
  • Searching for a town or city on /boards/ does not contact a geocoder. The first time you type in the search box, the page loads one more static file from this site (/boards/data/cities.json, built from GeoNames data under CC BY 4.0) and matches your input against it locally. What you type is never sent anywhere.
  • The location button on /boards/ is the only feature that asks your browser for a permission. If you activate it and allow the request, your browser determines your position and the map centres on it, drawing a dot and an accuracy circle. The coordinates are used only to move the map inside the open page: they are not transmitted to this site, to the tile server, or to anyone else, and nothing about them is stored. Declining the prompt, or never pressing the button, leaves the map exactly as it was.
  • /404.html, when reached via a /c/<naddr> URL, opens WebSocket connections to public Nostr relays (relay.damus.io, nos.lol, relay.primal.net) to fetch the metadata for a shared climb. No data is sent except the standard Nostr query.
  • /competitions/ is the one part of this site that is a small application. Its pages open WebSocket connections to Nostr relays — the ones the competition itself names, otherwise the same public defaults the Android app ships (relay.damus.io, nos.lol, relay.primal.net, nostr-pub.wellorder.net, nostr.oxtr.dev) — to read a competition and to publish what you sign. The relay operator sees your IP address and which competition you asked for; publishing under a fresh key does not change that, and no setting here can. These pages send no counter request of any kind: they carry no analytics script.
  • Signing in on /competitions/ never sends a private key anywhere, and there is no endpoint here that could receive one — the site is static. A browser extension or a remote signer keeps the key entirely outside this page. If you let the page generate a key instead, it is held in memory and, only if you choose to save it, written to your browser's localStorage as ciphertext under a passphrase you set. After you unlock that saved key, an additional reload-only copy is encrypted with a non-extractable browser key in IndexedDB; its ciphertext and random reference in sessionStorage limit it to the current tab, so a hard refresh does not ask for the passphrase again. The passphrase is never stored and cannot be reset. Choosing "shared device" writes nothing at all. Signing out, closing the tab, and an expired session remove this reload session and erase the key from memory.
  • What a competition publishes about you is public and permanent: your Nostr public key, the display name you choose, your division, and your results. Nostr events cannot reliably be deleted once relays have copied them. Your real name, contact details and anything about people who only viewed the page are never published. The display name appears on a public screen and on public relays; a nickname is fine and the registration form says so.

Anonymous aggregate counters

On a page load, the local /assets/anonymous-analytics.js script sends one first-party counter request to stats.cruxcoach.org; it sends another when you activate the Zapstore install option. The download page the in-app share QR resolves to (/get.html) carries the same page-view counter written directly into the page rather than loading that script, because it must survive on a single request; it counts under the label /app-share and follows every rule below unchanged. A direct-APK activation is counted by the same first-party request that selects and serves an available APK source, so it is not sent a second time by JavaScript. If the button was never pointed at that selector, because our server did not answer, the script counts the activation itself instead — otherwise an outage would read as a lack of interest. The script can additionally count one same-tab Zapstore-to-direct-APK fallback as described below. If your browser has Do Not Track or Global Privacy Control enabled, the script sends nothing, creates no fallback marker, and the selector skips its counter while still performing the download redirect.

  • A page view contains only a canonical page name such as /, /boards/, or /privacy.html. The Board Map's map and list views use the same /boards/ label; English and German remain separate. Query strings, fragments, referrers, and full URLs are not sent. Every /c/<naddr> share is reduced to the same /c/:share label; the share identifier never reaches the counter. Arrivals on the share-QR download page all report the single label /app-share.
  • An install click contains only the target (direct_apk or zapstore), placement (hero, install, or shared_climb), and the same canonical page name. This distinguishes public subpages without transmitting a full URL, query, or share identifier.
  • After a Zapstore activation, the script stores only its time in the current tab's sessionStorage. It contains no random or stable identifier, is never transmitted, expires after 30 minutes, is deleted by the first subsequent direct-APK activation, and disappears when the tab session ends. If that direct activation occurs within 30 minutes, the server receives one already-combined fallback event containing only the canonical page. It does not receive two linkable events or the elapsed time. The count is an interaction hint, not proof that Zapstore failed or deterred anyone.
  • The script requests explicitly omit credentials and the referrer; direct-APK links and redirect responses also set a no-referrer policy. No cookie, local-storage analytics ID, account/Nostr key, device ID, fingerprint, screen data, IP hash, or session/visitor identifier is created or transmitted. The selector reads a DNT/GPC header only to suppress counting and does not retain it.

The collector immediately increments an allowlisted UTC-day aggregate and retains no raw event, exact timestamp, request header, IP address, user agent, or referrer. Its own request logging and the dedicated reverse proxy's access logging are disabled. An IP address is necessarily processed transiently by network infrastructure to deliver the request, but it is not copied into the event payload or aggregate record, logged, hashed, or retained by our analytics stack. The resulting numbers are page views, clicks, and one explicitly defined fallback sequence — never counts of people, server sessions, or unique visitors. They are approximate: privacy signals, blockers, outages, reloads, repeated clicks, direct selector links, bots, and forged requests can all affect them. The collector and dashboard source are maintained in a private operational repository and are not publicly accessible. This does not affect the CruxCoach Android app: its source remains publicly available under its open-source license at codeberg.org/CruxCoach/CruxCoach.

Controller, purpose and legal basis

The controller for the first-party analytics processing at cruxcoach.org and stats.cruxcoach.org, including the planned app update event, is the maintainer of the non-commercial CruxCoach open-source project. Privacy enquiries can be sent to press@cruxcoach.org.

We use the website counters solely to understand which public pages are loaded, count activations of the two installation options, observe the coarse Zapstore-to-direct-APK fallback rate, and maintain and improve the site and its download paths. Starting with the planned app release 0.2.2, the verified-update counter will additionally show aggregate updater distribution by target version and source so we can monitor its uptake and reliability. To the extent that receiving a request involves personal data, the legal basis is Article 6(1)(f) GDPR. Our legitimate interests are the privacy-preserving operation, maintenance, and improvement of this non-commercial open-source project and its download distribution. We do not use the data for advertising, profiling, recognising people, or counting unique visitors.

Analytics hosting, recipients and retention

The endpoint at stats.cruxcoach.org runs on infrastructure provided by Hetzner Online GmbH at the selected Helsinki, Finland location. Hetzner provides the hosting infrastructure and necessarily handles connection data while delivering network traffic. The collector is not placed behind an analytics CDN or WAF. Access logging in the dedicated reverse proxy and collector is disabled; our analytics stack retains no raw request, IP address, user agent, referrer, or exact timestamp. The APK selector separately caches only public release metadata and the currently chosen source, never visitor data.

Accepted requests are folded immediately into UTC-day counters. Those aggregates are exported to metrics_anonymous.csv in the private operational repository and are not published publicly. They are retained without a fixed deletion period, including in repository history. They contain no raw event or identifier and cannot identify a person or link separate server events; the fallback sequence is combined locally before its single request.

Your choices and rights

Providing a website analytics event is not a statutory or contractual requirement. DNT or GPC suppresses website analytics without preventing the APK selector from redirecting. Blocking or failing a separate page-view or Zapstore-click counter does not affect navigation or downloading. If that hostname is blocked or unavailable, the direct-APK button simply stays on its Codeberg link and the download still works. Where the GDPR applies and the statutory conditions are met, you have rights of access, rectification, erasure, and restriction; data portability applies only where its separate legal conditions are met. Because no raw event or identifier is retained, after aggregation we normally cannot retrieve or isolate a visit or click relating to you. You may lodge a complaint with a supervisory authority, particularly in the Member State of your habitual residence, place of work, or the alleged infringement. There is no automated decision-making or profiling.

Right to object: You may object at any time, on grounds relating to your particular situation, to processing based on Article 6(1)(f) GDPR. You can contact us at press@cruxcoach.org; enabling DNT or GPC also suppresses website analytics requests technically.

Map tiles on /boards/

The map background on /boards/ is rendered from OpenStreetMap raster tiles served by tile.openstreetmap.org. While you are viewing that page, your browser sends requests directly to that host for every tile it needs to draw. Those requests are subject to OpenStreetMap's tile-usage policy and the OpenStreetMap Foundation's privacy policy. We have no insight into those requests; the only way to avoid them is to not load the map.

Opening hours on /boards/

Some venues on the board map show opening hours taken from OpenStreetMap. Those hours are fetched from this site as a static file, /boards/data/osm-opening-hours.json, which is refreshed occasionally by a build script on our side. Your browser therefore never asks OpenStreetMap — or anyone else — about a particular gym, and opening a venue's popup reveals nothing about which gym interests you. The only OpenStreetMap requests this page makes are the map tiles described above. The "View or correct these hours on OpenStreetMap" link is an ordinary external link and connects only when you click it.

What Codeberg does

This site is hosted by Codeberg e.V. on Codeberg Pages. Codeberg processes technical request metadata, including the IP address, browser and operating system, date and time, requested URL, and referrer, to provide the platform and prevent misuse. If technical metadata is written to logs, Codeberg says the IP address is truncated and the metadata is retained for no more than seven days unless German law requires otherwise. We have no access to it. See Codeberg's privacy policy for details.

External links

There is no visitor-side or pre-click APK availability probe. The first-party server checks source health without visitor data. If the button was pointed at our selector, activating it asks stats.cruxcoach.org whether it is still answering — it may have gone down since the page loaded — and then contacts it, which either serves the file itself or redirects you to the selected Codeberg or Zapstore source; only then does your browser connect to that provider. That first question goes to our own server about itself and counts nothing. If it was not — because our server did not answer, or because you have a privacy signal set, which suppresses the counter request that does the pointing — activating it asks us the same question anyway, and uses our own copy if we answer. Only when we do not does it connect you to Codeberg directly. In that one situation the script first asks Codeberg's release metadata endpoint whether the release is still there, waiting no longer than 1.5 seconds, and sends you to the Zapstore mirror instead if it is not. That question is asked only after your click, only when our own server is out of reach, and only to the provider your click was already headed for; it is never asked while you are merely reading the page, and the APK file itself is never requested for this. Other external links connect directly when clicked. Those services have their own privacy practices, which apply at the moment you connect:

  • Codeberg: codeberg.org/Codeberg/org/PrivacyPolicy.md
  • Zapstore: zapstore.dev/docs/faq
  • Mastodon (mastodon.social): mastodon.social/privacy-policy
  • Primal: primal.net

The Board Map and its venue directory additionally link to gym operators' own websites, for those venues where we manually verified that the site really belongs to that location. These are ordinary links and nothing else: while you read the page nothing is requested from any operator's site, no operator learns that you were here, and activating one transmits as the source only https://cruxcoach.org — never which venue you were looking at, and never a full URL. From that point the respective operator's own privacy practices apply.

Email

The address press@cruxcoach.org is forwarded to the project maintainer. Email content and routing metadata pass through the operator that provides the forwarding service. We retain no separate copy beyond what's needed to reply, and we don't use the address for any newsletter, marketing, or unsolicited contact.

The CruxCoach Android app

This page primarily describes cruxcoach.org. The CruxCoach Android app keeps personal data local by default, has no user tracking or accounts, and offers opt-in encrypted backup. Current release 0.2.1 sends no app-analytics event. The upcoming 0.2.2 release will add one aggregate increment after the optional in-app updater fully downloads an update and verifies its SHA-256 and signing certificate. The event will contain only the target version and source (codeberg/zapstore), never a device, installation, account, Nostr, advertising, or user identifier. A failed counter request will never affect update checking or installation. It will count verified updater downloads, not people or successful installs. The app's complete network behaviour is described on the main page and in the source repository at codeberg.org/CruxCoach/CruxCoach.
